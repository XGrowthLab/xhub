# 控制台更新与回退

平台管理员打开「管理员设置 → 版本更新」检查发布版本。页面展示当前版本、发布渠道、目标版本和说明。确认后，独立主机执行器校验并切换网关及控制台镜像。刷新页面可继续查看任务。服务器需要一次性的启用配置。

## 正式与测试发布

从已合入、完成检查的提交创建标签。正式版本以三段版本号命名，例如 v0.1.0。首个测试发布使用 v0.1.0-beta.1。后续测试版使用 beta.2、beta.3 等，供已开启测试渠道的实例验证。

标签触发既有完整验证及两份镜像构建。通过后 GitHub Release 附带 docker-images.txt 和 xhub-release.json。后者绑定提交、镜像摘要和保守的数据库兼容标识。预发布不会更新 latest。已发布的清单不可改写，变动应使用新版本号。

## 主机启用

需要 Python 3.10+、Docker Compose v2、已经装好同一标记版本的两个发布镜像。自建环境可以选择不启用。既有非正式镜像或不同提交的网关与控制台，先按正常主机发布流程安装成套版本。

1. 将 deploy/update_agent.py 与 deploy/update_manifest.py 安装在同一只允许主机管理员修改的目录，例如 /opt/xhub-updater。
2. 拷贝 deploy/xhub-updater.service.example 为自己的 systemd 服务并校对 Compose 绝对路径、项目名、发布入口及健康地址。默认从固定 GitHub 项目读取发布。私有仓库可在受保护的 EnvironmentFile 中配置只读 XHUB_RELEASE_TOKEN。镜像仓库凭据由主机 Docker 管理。
3. 网关设置 XHUB_UPDATE_SOCKET=/run/xhub-updater/agent.sock，并将 /run/xhub-updater 目录只读挂载到容器同一路径。挂载目录可在进程重启后重新连接新的套接字。目录与套接字的访问权限需允许网关进程。
4. 启动主机服务并按一次性部署步骤重建网关。默认正式渠道。测试实例可在服务的 ExecStart 末尾加 --allow-beta。私有镜像源或离线场景可由主机管理员提供 --namespace 及 --manifest-file。

默认健康地址为 http://127.0.0.1:4000/health/readiness 和 http://127.0.0.1:3000/login。端口不一致时分别提供两个 --health-url 参数。管理接口只访问这个 Unix socket，Docker 权限留在执行器。项目下应只有一个网关和一个控制台实例。

## 切换与恢复

执行器在下载和校验两份镜像后，给网关停机时的在途 HTTP 与 SSE 留出最多一分钟。单网关切换期间可能短暂不可用。执行器使用 Compose 的 --no-deps，只替换两个应用服务。它记录上一版本及待完成切换，新版本不健康或进程中断时尝试恢复原镜像。恢复失败会保留记录并阻止后续操作。

执行器维护状态目录中的 compose.override.json。启用执行器后，人工运行 Compose 时应在原文件之后添加该覆盖文件，保持应用与指定摘要一致。不要删除上一版本镜像，直到不再需要该回退点。state.json 保留事务、操作者和最近回退依据，按实例运维权限保管。

第一期要求两个版本的数据库兼容标识一致。该标识保守覆盖启动和持久层的源文件，变化会让 UI 阻止直接升级，包括没有改变数据库结构的部分改动。验证相容性和需要迁移的版本仍走主机部署流程。数据库备份和恢复见[部署备份盘点与轮换](deployment-backup-rotation.md)。
